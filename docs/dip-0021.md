# DIP 21: Payment URIs for Dogecoin and DogecoinVM

```
DIP: 21
Title: Payment URIs for Dogecoin and DogecoinVM
Author: Paulo Vidal <https://github.com/qlpqlp>
Status: Draft
Type: Standards Track
Created: 2026-10-09
```

This is a draft variation of [BIP 21](https://github.com/bitcoin/bips/blob/master/bip-0021.mediawiki). Dogecoin's [standards repository](https://github.com/dogecoin/dips) numbers a DIP with the BIP it adapts. This number is not assigned there yet.

## Abstract

Dogecoin payments already use BIP 21 with the scheme `dogecoin:`. DogecoinVM uses the same address bytes, so a `D…` address by itself does not say which ledger to pay. This DIP leaves `dogecoin:` as the Dogecoin payment URI and defines `dogecoinvm:` for a DogecoinVM payment, with the same query syntax. A wallet reads the scheme and chooses the chain.

## Motivation

One Dogecoin key has the same address on Dogecoin and on DogecoinVM. Mainnet P2PKH, P2SH, and WIF versions are 30, 22, and 158 on both. Testnet versions are 113, 196, and 241 on both. The coins sit in two different UTXO sets.

A receive QR that is only the address can be paid on the wrong chain. BIP 21 already gives Dogecoin a scheme. The same grammar with a second scheme gives a wallet an explicit chain, in a link and in a QR, without a new address format.

This does not change how either chain validates a transaction. It only tells software which chain the request is for.

## Specification

A payment URI follows BIP 21 and RFC 3986. The scheme selects the ledger. The path is the address. The query carries the optional payment fields.

```
payment-uri = scheme ":" address [ "?" params ]
scheme      = "dogecoin" / "dogecoinvm"
address     = 1*base58
params      = param *( "&" param )
param       = [ "req-" ] key "=" *qchar
```

The scheme is case-insensitive. `DogecoinVM:` and `dogecoinvm:` are the same request. The address is case-sensitive. There is no `//` authority component: the form is `dogecoinvm:D…`, not `dogecoinvm://D…`.

| Scheme | Pay on |
| --- | --- |
| `dogecoin:` | Dogecoin, the proof-of-work chain |
| `dogecoinvm:` | DogecoinVM |

`dogecoin:` is the URI Dogecoin Core has implemented since v1.0.0, as recorded in Dogecoin's `doc/bips.md`. This DIP does not change that scheme.

### Address

The address is a Dogecoin base58 P2PKH or P2SH address. Version bytes:

| | Mainnet | Testnet |
| --- | --- | --- |
| P2PKH | 30 | 113 |
| P2SH | 22 | 196 |

The address version selects mainnet or testnet. The scheme selects Dogecoin or DogecoinVM. A testnet request is `dogecoinvm:` plus a testnet address, not a different scheme.

A wallet MUST reject a URI whose address is not a valid address for the network it is about to pay.

### Query parameters

Parameters are percent-encoded. Keys are case-sensitive. The BIP 21 keys mean the same thing on both schemes:

| Key | Meaning |
| --- | --- |
| `amount` | Amount of DOGE to send. Decimal, no thousands separators, `.` as the decimal point, at most 8 decimal places. `amount=50.00` and `amount=50` are 50 DOGE. `amount=50,000.00` is invalid. |
| `label` | A name for the receiver, shown to the sender. Not put on the chain. |
| `message` | A note describing the payment, shown to the sender. Not put on the chain. |

A parameter whose name starts with `req-` is required. If the wallet does not understand it, the wallet MUST refuse the URI. Any other parameter the wallet does not understand MUST be ignored. That keeps room for later extensions without breaking today's wallets.

`amount` is denominated in DOGE on both schemes, never in koinu.

### What a wallet does

| URI | Dogecoin-only wallet | DogecoinVM-only wallet | Wallet that can pay both |
| --- | --- | --- | --- |
| `dogecoin:…` | Pay Dogecoin | Refuse | Pay Dogecoin |
| `dogecoinvm:…` | Refuse | Pay DogecoinVM | Pay DogecoinVM |
| Bare address, no scheme | Pay Dogecoin, as today | Pay DogecoinVM | Ask which chain. Do not guess |

Refusing an unknown scheme means showing an error and not building a transaction. A wallet MUST NOT strip `dogecoinvm:` and pay that address on Dogecoin, and MUST NOT strip `dogecoin:` and pay that address on DogecoinVM. The address can be valid on both, and the coins are not the same outputs.

A receive screen SHOULD encode a full URI, not a bare address, and SHOULD use the scheme of the chain whose balance is being shown. An optional amount is `?amount=` in DOGE.

A scanned URI fills the send form for that chain. The user still confirms the chain, the address, and the amount before broadcast.

### Out of scope

A `dogecoinvm:` URI is a payment on DogecoinVM. It is not a bridge deposit and it does not create a peg-in. Moving DOGE between Dogecoin and DogecoinVM stays a bridge operation, with its own tags, as described in [BRIDGE.md](BRIDGE.md).

Parameters defined elsewhere for Dogecoin payment links, including DogeConnect's `dc` and `h` on `dogecoin:` URIs, are unchanged. This DIP does not require them on `dogecoinvm:`.

## Examples

Dogecoin, address only:

```
dogecoin:DFundReceiverAddressxxxxxxxxxxxxxxxxxx
```

Dogecoin, 8.25 DOGE with a label and a message:

```
dogecoin:DFundReceiverAddressxxxxxxxxxxxxxxxxxx?amount=8.25&label=Shop&message=Order%20123
```

DogecoinVM, address only:

```
dogecoinvm:DFundReceiverAddressxxxxxxxxxxxxxxxxxx
```

DogecoinVM, 1.5 DOGE:

```
dogecoinvm:DFundReceiverAddressxxxxxxxxxxxxxxxxxx?amount=1.5&label=VM%20tip
```

The same address string may appear after either scheme. Each URI still names a different ledger.

## Rationale

BIP 21 already solved payment links for a single chain: scheme, address, then `amount`, `label`, and `message`. Dogecoin shipped that as `dogecoin:`. DogecoinVM does not need a new query language. It needs a scheme that existing BIP 21 parsers can branch on.

Putting the chain in the address, or in a query parameter such as `?chain=vm`, would break that. A wallet that does not know the parameter would ignore it and pay Dogecoin. A separate scheme cannot be ignored safely: BIP 21 clients that do not recognise the scheme fail the request, which is the behaviour this DIP requires.

## Backwards compatibility

`dogecoin:` URIs stay valid. Dogecoin Core and every other BIP 21 Dogecoin wallet keep working.

`dogecoinvm:` is new. Older Dogecoin wallets do not recognise it. They are required to refuse it rather than pay Dogecoin. Dual-chain wallets that today emit `dogecoin:` for a DogecoinVM receive QR should switch that QR to `dogecoinvm:`, or a Dogecoin wallet that scans it will pay the wrong chain.

Bare addresses stay bare addresses. This DIP does not reinterpret them.

## Reference implementation

No wallet in this repository parses payment URIs yet. The scheme names and query rules above are the specification those wallets implement.
